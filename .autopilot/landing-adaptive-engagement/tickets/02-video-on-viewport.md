# 02 — Видео грузится по входу во вьюпорт, а не при загрузке страницы

**Требования:** R04, R04.1, R04.2, R04.3, R20i
**Blocked by:** —
**Зона:** `src/components/landing/VideoSection.tsx`, `src/hooks/`
**Волна:** 1
**Status:** ready

## Что должно заработать

Человек открыл страницу и не долистал до секции «Для этого рынка» — 2,4 МБ видео
не скачались. Долистал — видео стартует без заметной паузы, потому что загрузка
началась заранее, с запасом. Ушёл со секции — воспроизведение встало.

## Из брифа, дословно

> «Видео 2,5 МБ качается при каждой загрузке (`play()` на mount, а не по входу во вьюпорт).»

## Разделы спецификации

Истории 32–36. Границы: модуль `viewport-media`, `useInViewport(ref, {rootMargin}) -> boolean`.

## Что сейчас в коде

`VideoSection.tsx` вызывает `play()` внутри `useEffect` на монтировании; `IntersectionObserver`
отсутствует; `preload="metadata"`. Файл `public/video/trucks.mp4` — 2 521 594 байта
(в брифе названо 2,5 МБ, фактически 2,4 МиБ).

## Критерии приёмки

- [ ] До появления секции во вьюпорте во вкладке «Сеть» нет запроса `trucks.mp4`
- [ ] Запас на упреждение задан так, что к моменту появления секции кадр уже идёт
- [ ] Постер держит кадр до старта, разметка не прыгает (нулевой сдвиг макета)
- [ ] Уход секции из вида ставит воспроизведение на паузу
- [ ] Существующее уважение к `prefers-reduced-motion` через класс `motion-ok` сохранено:
      при выключенном движении видео не играет ни при каком скролле
- [ ] Браузер без `IntersectionObserver` получает постер, а не пустоту
- [ ] `npm run build` зелёный
