## Что должно заработать

В стилях лендинга остаётся ровно четыре значения ширины — `430`, `768`, `980`, `1280` —
и две точки по высоте: `700` и `860`. Числа объявлены один раз, все правила ссылаются
на имена. Внешне страница не меняется нигде: это перекладка системы координат, а не
изменение вида. Любое расхождение с текущим видом — либо намеренное и записанное,
либо дефект.

## Из брифа, дословно

> «Плюс сведение 16 пиксельных порогов к четырём.»

## Разделы спецификации

Истории 1–4, Решения §1. Точная арифметика поглощения — таблица в разделе «Как выбраны
четыре»: 17 порогов снимаются, 3 остаются, 1 (`1280`) добавляется вместо 1060/1100.

## Важное про пересчёт

В брифе сказано «16 порогов». Их **20 по ширине и 1 по высоте**. Число из брифа не
подтвердилось — работай по факту в коде, а не по брифу, и напиши в отчёте таска,
сколько было на самом деле.

## Критерии приёмки

- [ ] `grep -o "[0-9]\+px" ` по `@media` в `src/styles` и `globals.css` находит только
      430, 768, 980, 1280 (ширина) и 700, 900 (высота)
- [ ] Числа записаны в одном месте; правила используют имена, а не литералы
- [ ] Для каждого снятого порога в отчёте таска сказано, в какой из четырёх он ушёл
- [ ] `npm run build` зелёный, `npm run lint` без новых замечаний
- [ ] Правило `@media (min-width: 980px) and (max-height: 760px)` заменено на высотную
      шкалу: компактный режим 700–900, ниже 700 пин выключается (само поведение
      пин-сцены делает таск 04 — здесь только шкала)
- [ ] Ничего не сломалось визуально: сравнение до/после на 320, 430, 768, 1024, 1440
      в обеих темах приложено к отчёту таска
