# 0006. D04 — обрез карточек истории на 320 и честный измеритель помещаемости

## Контекст

320 px — ширина приёмки по брифу (R07). Исполнитель таска 06 заявил `docOverflowX = 0`:
горизонтального переполнения страницы нет, значит на 320 всё цело.

## Решение

Код доказал обратное: на вьюпорте 320 колонка `.scrolly-grid` растягивается по min-content первого
кадра (`.dc-tabs` 320 → карточка 348) при содержимом страницы 310, и **все четыре карточки истории
режутся справа примерно на 56 px**. Дефект старше этой работы. Он чинится внутри волны: принять
волну с обрезом на ширине приёмки нельзя. Причина двойная — `1fr` = `minmax(auto, 1fr)` **и**
`margin: 0 auto`, отменяющий растяжение грид-элемента; барьеров поставлено два независимых.
Помещаемость измеряется как `scrollWidth − clientWidth` по карточке **и всем её потомкам**.

## Почему

- **Поверить `docOverflowX = 0`** отвергнуто: горизонтальный скролл прячет `body`, поэтому замер
  страницы не доказывает ничего. Обрез виден только на кадре `320-light-step1.png` — обрывается ряд
  вкладок и строка «конфиденциальное — по ролям».
- **Записать как потерянное требование Б8** отвергнуто: ни одна строка Б8 не называет
  `.scrolly-grid`. Это находка сборки класса D01/D02, а не требование, которое кто-то не донёс.
- **Вынести отдельным тикетом на потом** отвергнуто: бриф делает 320 шириной приёмки.
- **Снять один барьер и поставить негативный контроль на второй** отвергнуто: одиночный контроль
  остаётся зелёным при живом дефекте, потому что второй барьер его маскирует. Контроль ставится
  парами, по барьеру.

## Последствия

- Находка вне своей зоны нарезается отдельным таском (08, коммит `f54c176`), а не правится внутри
  чужого — иначе теряется соответствие «таск → требование».
- Инвариант записан в `interfaces.md`: мерить по элементу и потомкам, негативный контроль — парами.
- Два независимых барьера означают, что удаление любого одного дефект не вернёт и потому **не будет
  замечено**; их держит только записанный инвариант, а не падающий тест.
